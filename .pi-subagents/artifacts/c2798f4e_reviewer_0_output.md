## Review
- **Blocker / High — `src/app/swarm.rs:392,503,515`:** `answered` persists across rounds. If a persona succeeds in round 1 but returns an error or empty response in round 2, its old index remains present and the moderator still runs after round 2. Track successful responses per round—clearing the set at each round boundary—and add a regression test for success followed by failure.
- **Medium — `src/app/swarm.rs:221-231,315-324`:** Progress updates overwrite persisted errors. Errors are stored as `research_stage` content beginning with `swarm:`, and the next progress update selects the latest matching row and replaces it; the in-memory reverse search does the same. Use a distinct error role/label or track the dedicated progress row by ID.
- **Medium — `src/app/swarm.rs:462-475`:** Tool-specific progress is not emitted while the tool runs. The consumed `StreamEvent::Status` is sent only after `toolbox.run(...).await` completes (`src/provider/openrouter.rs:609-616`) and is immediately followed by the tool summary. Long-running tools therefore show only generic persona progress until completion. Emit a tool-start/status event before awaiting execution.
- **Note — `src/app/swarm.rs:734-744`:** The added test only checks the cumulative index helper. It does not exercise round resets, failed/empty streams, added-persona scheduling, timeout abortion, token collection across tool iterations, or progress persistence.
